## 1. 프로젝트 개요 ผ(•̀_•́ผ)

**"배송비는 나누고, 가치는 더하는 우리 동네 공동구매 플랫폼, 몇띵"**

1인 가구의 증가와 치솟는 물가 속에서, 온라인 쇼핑 시 발생하는 '배송비'는 소비자에게 적지 않은 부담으로 다가옵니다. 특히 소량의 물품이 필요할 때 배송비가 물품 가격과 맞먹거나, 무료 배송 기준을 채우기 위해 불필요한 과소비를 하게 되는 경우가 빈번합니다. 기존에도 커뮤니티를 통해 공동구매(이하 '공구')가 이루어지고 있으나, 모집 현황 파악의 어려움, 수동적인 금액 계산 및 입금 확인의 번거로움, 그리고 참여자의 "노쇼(No-show)" 문제 등 잦은 마찰이 발생하고 있습니다.

'몇띵'은 이러한 불편함을 해소하기 위해 탄생한 스마트 공동구매 매칭 플랫폼입니다. 공구 주최자인 '띵장'과 참여자인 '띵원'을 쉽고 투명하게 연결합니다. 특히, 띵장이 수용 가능한 '인당 배송비'를 설정하면 조건 충족 시 **공구가 자동으로 확정되는 시스템**을 도입하여 모집 과정을 단축했습니다. 또한, 모든 참여자의 구매 내역과 실시간 예상 배송비를 투명하게 공개하고, 체계적인 페널티 제도를 도입하여 신뢰 기반의 안전한 거래 환경을 제공합니다.

## 2. 프로젝트 목표 ( •̀ .̫ •́ )✧

**1) 배송비 부담 최소화 및 자동화 로직 구현**

- 무료 배송 기준액이나 사용자가 설정한 '인당 최대 배송비' 조건에 도달하면 즉각적으로 공구를 확정 짓는 자동화 알고리즘을 구현하여, 사용자의 대기 시간을 줄이고 거래 성사율을 높입니다.

**2) 투명하고 신뢰할 수 있는 협력 플랫폼 구축**

- 단순한 거래를 넘어, 띵장과 띵원이 서로 원활하게 소통하고 협력할 수 있는 환경을 조성합니다. 실시간 모금액, 참여 인원, 개인별 결제 예정 금액 등을 투명하게 공개하여 상호 간의 불필요한 오해나 마찰을 방지합니다.

**3) 악성 유저 방지를 통한 사용자 경험(UX) 보호**

- 입금 지연 및 미입금자에 대한 명확한 페널티 시스템(이용 정지 등)과 공구 재오픈 기능을 통해 주최자의 피해를 최소화하고 플랫폼 내 자정 작용을 유도합니다.

## **주요 기능 ヾ(•ω•`)**

**1. 조건부 자동 확정 스마트 로직**
기존 공동구매의 기약 없는 대기 시간과 수동 확인의 번거로움을 없애기 위해, 설정된 조건 도달 시 즉시 공구가 확정되는 알고리즘을 도입

- **자동 확정 조건 (둘 중 하나 충족 시 즉시 확정)**
→ **[조건 A]** 총 모금액이 띵장이 설정한 '무료 배송 기준 금액'을 충족했을 때
→ **[조건 B]** (배송비 ÷ 현재 참여 인원)이 띵장이 수용 가능하다고 설정한 '인당 배송비' 이하로 떨어졌을 때
- 크라우드 펀딩의 달성률 시스템처럼, 목표 조건이 충족되면 백그라운드에서 즉각적으로 상태가 변경되어 거래 성사율을 극대화하고 대기 시간을 단축합니다.

**2. 투명한 실시간 분담금 계산 및 스마트 알림 시스템**
복잡한 더치페이 계산과 일일이 입금을 안내해야 하는 주최자의 피로도를 시스템이 대체

- **실시간 데이터 렌더링:** 게시물 내에서 누적 공구 금액, 무료 배송까지 남은 금액, 그리고 인원 추가에 따라 실시간으로 저렴해지는 '1/N 예상 배송비'를 시각적으로 제공합니다.
- **자동 정산 알림:** 공구가 확정되는 즉시, 참여자 전원에게 띵장의 계좌번호와 함께 [본인 구매 물품 금액 + 최종 1/N 배송비]가 정확히 합산된 개별 입금 요청 알림이 발송됩니다.

**3. 노쇼(No-show) 방지 페널티 기능**
공동구매에서 가장 빈번하게 발생하는 '미입금' 문제를 해결하고, 쾌적한 플랫폼 환경을 유지하기 위한 강력한 사후 관리 및 신뢰도 검증 시스템입니다.

- **누적 페널티 제도:** 미입금 유저에게는 횟수에 따른 강력한 제재(1회 3일 정지 / 2회 2주 정지 / 3회 영구 탈퇴)가 가해지며, 닉네임 옆에 경고 횟수가 영구적으로 박제되어 악성 유저를 사전에 필터링합니다.
- **공구 재오픈(Rescue) 로직:** 미입금자 발생으로 공구가 무산될 위기에 처했을 때, 띵장은 미입금자만 시스템에서 제외한 후, 정상적으로 입금한 참여자들은 유지한 채 게시물을 즉시 재오픈(모집)하여 피해를 최소화할 수 있습니다.

**4. 부가 기능**

- **맞춤형 필터링 탐색:** 띵원이 원하는 물건의 카테고리와 거래 가능 장소(ex. 교내 특정 건물, 기숙사 앞 등 다중 선택 가능)가 일치하는 맞춤형 공구 게시물만 모아보기.
- **이용 내역 관리:** 마이페이지에서 내가 주최한(띵장) 공구와 참여한(띵원) 공구의 현재 진행 상태 및 과거 이력 통합 조회.

## FE (Frontend)🍮

### 주요 기능**ヾ(•ω•`)**

1.  **공동구매 모집 및 현황 표시**
- 📍 건물 및 장소별 공동구매 현황 시각화.
    - 예: 경북대학교 내부 장소 기반(농장문, 누리관문, 첨성관, 북문 등) 수령 가능 위치 구분
- 공동구매 카테고리별 분류 기능 제공.
    - 식품 🍜, 문구류 ✏️, 의류 👕,
    - 생활용품 🏠, 뷰티 💄, 도서 📚, 기타 📦
    
1. **공동구매 상태 관리**
- 🟡 `OPEN` : 모집 중
- 🟢 `CONFIRMED` : 공구 확정
- 🟣 `ARRIVED` : 상품 도착
- 🔵 `COMPLETED` : 수령 완료

1. **시간표 UX 기반 거래 시간 관리**
- 대학생들의 현실적인 캠퍼스 동선을 고려한 시간표 슬롯 기반  조율 시스템 구축.
    - 📆 요일 정의(`WEEK_DAYS`): 월요일부터 일요일까지 선택 가능.
    - ⏰ 시간대 정의(`TIME_SLOTS`): 30분 단위의 세부 거래 시간 제공.
- 중복 예약 방지🚫 제약조건을 통한 예약 충돌 차단.

1.  **참여 및 정산 내역 관리**
- 개인 이용 이력 및 공동구매 개설/ 참여 내역 따로 확인 가능.
    - 내가 띵장인 공구(`hosted Posts`)와 내가 띵원인 공구(`joined Posts`)를 분리하여 직관적인 UI 제공.
- 배송비 분할 정산 연산 및 실시간 상태 안내.
    - 무료배송 목표 금액 달성 여부에 따른 배송비 면제 표시.
    - 입금 흐름 상태값(`paymentStatus`) 연동:  `PENDING` (입금 대기), `SENT` (송금 완료), `APPROVED` (승인 완료).
- 실시간 알림 아키텍처 연동.
    - 읽지 않은 알림 개수(`unread NotificationsCount`) 실시간 카운팅 표기.

### **UI/UX 디자인**

- 현대적인 디자인 시스템 적용.
    - `backdrop-filter: blur(12px)` 속성을 활용하여 디자인

    - ShoppingBag, MapPin, Bell, CreditCard, Calendar 등 상황에 최적화된 컴포넌트 시각화 구성.

## BE (Backend)🍮

### API 명세서

- Express 미들웨어(`app.use(express.json())`) 기반의 구조화된 JSON 응답 및 통신 구현. HTTP Method를 통해 행위의 목적을 명확히 규정한 RESTful 패턴 설계.
- 인증/유저
    
    
    | **Method** | **URL Path** | **설명** |
    | --- | --- | --- |
    | `POST` | `/api/v1/auth/signup` | 일반 회원가입 (비밀번호 SHA-256 암호화 적용, 가입 즉시 JWT 토큰 발급) |
    | `POST` | `/api/v1/auth/login` | 일반 로그인 (ID/PW 검증 후 7일간 유효한 JWT 토큰 및 유저 상태 반환) |
    | `GET` | `/api/v1/users/me` | 내 프로필 및 계정 상태(벌점, 제재 여부 등) 상세 조회 |
    | `GET` | `/api/v1/users/me/hosted` | 내가 띵장(호스트)으로 개설한 공동구매 방 목록 조회 |
    | `GET` | `/api/v1/users/me/joined` | 내가 띵원(참여자)으로 참여한 공동구매 방 목록 조회 |
- 공동 구매
    
    
    | `POST` | `/api/v1/posts` | 공구 방 생성 (호스트 아이템 필수 포함, 조건 만족 시 즉시 `CONFIRMED` 처리 및 알림 발송) |
    | --- | --- | --- |
    | `GET` | `/api/v1/posts` | 공구 목록 전체 조회 (카테고리 필터 및 다중 픽업 지역 교집합/합집합 필터링 지원) |
    | `GET` | `/api/v1/posts/:postId` | 공구 상세 정보 조회 (현재 참여 인원 기준 1/N 배송비 및 무료 배송 여부 실시간 계산 데이터 반환) |
    | `PATCH` | `/api/v1/posts/:id` | 공동구매 수명 주기 진행 상황(Lifecycle) 및 정산 상태 변경 |
    | `DELETE` | `/api/v1/posts/:id` | 특정 공동구매 모집 글 파기 및 관련 예약을 연쇄 삭제 |
- 참여/ 정산
    
    
    | `POST` | `/api/v1/posts/:postId/join` | 공구 참여 (배송비 승인 약관 동의 필수, 기존 참여 기록은 덮어쓰며 조건 충족 시 방을 `CONFIRMED`로 격상) |
    | --- | --- | --- |
    | `GET` | `/api/v1/posts/:postId/members` | 참여자 명단 조회 (유저별 주문 아이템 목록, 입금 상태, 상품 금액 + 1/N 배송비가 합산된 최종 실입금액 산출) |
    | `GET` | `/api/v1/posts/:postId/account` | **[보안 Lock]** 확정된 방(`CONFIRMED` 이상)의 실참여자 및 호스트에게만 띵장의 실제 계좌번호와 실명 개방 |
    | `POST` | `/api/v1/posts/:postId/payment/send` | 띵원이 호스트에게 계좌 송금을 완료했음을 신고 (`paymentStatus`를 `SENT`로 변경) |
    | `POST` | `/api/v1/posts/:postId/payment/approve/:userId` | **[호스트]** 입금 확인 최종 승인 (`CONFIRMED` 시점 기준 24시간 연체 시 벌점 부여 및 이용 정지 스케줄 적용) |
- 구조
    
    
    | `POST` | `/api/v1/posts/:postId/rescue` | **[호스트]** 미입금자 수동 방출 후 후속 조치 (`RE_OPEN`으로 재모집하거나 `SPLIT_REMAINING`으로 남은 인원끼리 독박 배송비 N분의 1 재계산 알림 발송) |
    | --- | --- | --- |
- 수령/알림
    
    
    | `POST` | `/api/v1/posts/:postId/arrive` | **[호스트]** 배송 물품 도착 선언 (방 상태를 `ARRIVED`로 변경하고 띵원들에게 수령 시간표 예약 시작 푸시 알림 발송) |
    | --- | --- | --- |
    | `POST` | `/api/v1/posts/:postId/timetable` | **[호스트]** 물품을 배부할 수 있는 위클리 수령 가능 시간대 슬롯 목록 등록 |
    | `POST` | `/api/v1/posts/:postId/pickup` | 띵원의 픽업 장소 및 시간표 선착순 예약 (30분 단위 검증, 1인 1슬롯 제한, 동일 시간대 타 장소 선점 시 예약 충돌 방지 로직 작동) |
    | `GET` | `/api/v1/posts/:postId/pickup/bookings` | 해당 공구 방에 등록된 모든 멤버들의 시간표 예약 현황을 실시간 타임스탬프 기준으로 정렬하여 조회 |
    | `GET` | `/api/v1/notifications` | 로그인한 유저 개인의 실시간 알림(공구 확정, 물품 도착, 방출 안내 등) 수신함 전체 조회 |
    | `PATCH` | `/api/v1/notifications/:id/read` | 특정 알림 ID를 읽음(`read = 1`) 처리 |

### DataBase 구조

- 파일 하나에 전체 데이터를 영속화하는 가볍고 빠른 경량 데이터베이스 시스템 SQLite(`dding.db`) 구축.
- 데이터 무결성을 유지하기 위해 `PRAGMA foreign_keys = ON;`을 사용하여 연관 레코드 동시 제어 강제.

### 주요 기능 **ヾ(•ω•`)**

1.  토큰 기반 Stateless 인증 시스템(로그인 및 보안 기능)
- 회원가입
    - 비밀번호 SHA-256 암호화
    - DB에는 해시값만 저장
- 로그인
    - JWT 발급
- 인증 과정
    - 로그인 → JMT 발급 → Authorization Header → JMT 검증 →API 접근 허용
1. 실시간 배송비 정산 및 알림 연계
- 공구 확정 시 배송비를 참여 인원수로 나누어 소수점 반올림 후 인당 배송비 산정
- 무료배송 처리:  총 금액이 ≥무료 배송 목표 →  배송 청구 비용을 0원으로 자동 변동 처리
- 알림 생성: 고유 알림 ID 생성 → 유형별 푸시 알림 DB 저장
1. 미입금 대응 자동화 제재 로직 (Rescue Checks)
- 재모집
    
    공구확정→ 미입금자 발생 → 띵장 확인 → 재오픈 선택 → 미입금자 패널티 자동 누적 → 미입금자 제외 공구 재모집 진행
    
- 배송비 재분담
    
     공구확정→ 미입금자 발생 → 띵장 확인 → 배송비 재분담 선택 → 미입금자 패널티 자동 누적 → 남은 인원 기준 배송비 1/N 재계산

## 확장 가능성 및 마무리

- 대학 기숙사 및 자취촌 배달 연계
    ◦ 단순 물품 공동구매를 넘어, 기숙사나 자취촌의 높은 1인분 배달비 문제를 해결하는 '캠퍼스 실시간 배달팟 매칭' 서비스로 즉각 확장 가능
- 학내 중고거래 및 덤(나눔) 시스템
    ◦ 시간표 UX를 그대로 활용하여 전공 서적, 자취방 물품 등 학내 구성원 간의 안전한 '공강 시간 1:1 중고거래 픽업 매칭' 기능으로 고도화 가능
- 로컬 상권 활성화 인터페이스
    ◦ 학교 앞 음식점, 카페 등 대학가 로컬 상권과 연계하여 '대학생 단체 할인/학생 전용 마트 공구 딜' 등의 비즈니스 모델을 결합한 캠퍼스 특화 커뮤니티 플랫폼으로 발전 가능
